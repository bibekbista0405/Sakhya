# Sakhya calling implementation

Calling is implemented as real WebRTC media with Socket.IO signaling. It is not a demo stream.

## What was fixed
- Real microphone/camera MediaStreams are attached to RTCPeerConnection.
- Trickle ICE candidates are forwarded with strict call authorization.
- Call UI now waits for actual WebRTC `connected` state before starting the timer.
- Remote audio/video tracks are attached to autoplay/playsInline media elements.
- Connection failures and 30-second connection timeouts clean up both sides.
- Calls cannot overlap for a user; busy callers receive a clear error.
- Accepted calls are only marked completed after WebRTC actually connects.
- Stale unanswered calls expire after 45 seconds.
- Disconnecting either side terminates the active call cleanly.
- Optional TURN configuration is supported through NEXT_PUBLIC_TURN_URL, NEXT_PUBLIC_TURN_USERNAME and NEXT_PUBLIC_TURN_CREDENTIAL.

## Production requirement
STUN can establish direct peer-to-peer connections when NAT allows it. For reliable calls between arbitrary networks, mobile carriers, office Wi-Fi, CGNAT and restrictive firewalls, configure a TURN server (for example a self-hosted coturn instance) and provide its credentials through the client environment variables.

Never commit long-lived TURN credentials to a public repository. Prefer short-lived TURN credentials generated by your backend for production.
